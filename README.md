# Практическая работа №3. Система «Платежи» (вариант 2)

Реализация консольного приложения на C# (.NET 9) по материалам практических работ №1 и №2:
UML-диаграмма классов, сценарий оплаты заказа, принципы SRP и OCP.

## Что входит в работу

| Путь | Назначение |
| --- | --- |
| `Практика 3_Матийцива О.Р..docx` | Отчёт по практической работе (29 страниц, 8 рисунков, 9 таблиц, листинги) |
| `Практика 3_Матийцива О.Р..pdf` | PDF-версия отчёта |
| `src/Payments.WithoutPrinciples` | Версия без применения SRP и OCP (монолитный `PaymentSystem`) |
| `src/Payments.WithPrinciples` | Версия с SRP и OCP (домен, сервисы, правила, инструменты, инфраструктура) |
| `tests/Payments.Tests` | 13 модульных тестов версии с принципами |
| `docs/img` | UML-диаграммы и протоколы выполнения |
| `docs/output_*.txt` | Полные протоколы работы приложений |
| `tools` | Скрипты генерации диаграмм, изображений консоли и отчёта |

## Запуск

Требуется .NET SDK 9.0.

```bash
dotnet run --project src/Payments.WithoutPrinciples
dotnet run --project src/Payments.WithPrinciples
dotnet run --project tests/Payments.Tests
```

Все три команды можно выполнить из корня репозитория. Проект тестов возвращает код 0,
если все 13 проверок пройдены.

Если `dotnet` в терминале или Visual Studio не находит SDK, воспользуйтесь `build.cmd`:
он запускает сборку через x64-версию .NET SDK и не зависит от порядка путей в `PATH`.

## Если Visual Studio пишет «не удалось найти пакет SDK Microsoft.NET.Sdk»

Это не ошибка проекта, а настройка окружения: в системном `PATH` первой стоит
x86-версия `dotnet` (`C:\Program Files (x86)\dotnet`), в которой нет SDK, а SDK 9.0
установлен в x64-каталоге `C:\Program Files\dotnet`.

Вариант 1 (без прав администратора):

1. Закрыть Visual Studio.
2. `Win+R` → `sysdm.cpl` → «Дополнительно» → «Переменные среды».
3. В верхнем блоке («Переменные среды пользователя») создать переменную
   `DOTNET_MSBUILD_SDK_RESOLVER_CLI_DIR` со значением `C:\Program Files\dotnet`.
4. Открыть решение заново и собрать.

Вариант 2 (правильный, нужны права администратора): в системной переменной `Path`
переместить `C:\Program Files\dotnet` выше `C:\Program Files (x86)\dotnet`.

## Кратко о результате

Обе версии реализуют один и тот же набор из десяти сценариев и дают одинаковый
бизнес-результат: оплата картой, оплата со счёта с комиссией 1 %, отказ при превышении
кредитного лимита, перевод между счетами, блокировка карты клиентом и администратором,
оплата бонусными баллами, аннулирование счёта.

Версия с SRP/OCP дополнительно демонстрирует расширение без изменения существующего кода:
правило `DailyLimitRule` и способ оплаты `BonusPaymentInstrument` подключаются в
композиционном корне, а `OrderPaymentService` остаётся неизменным.
